# Salla & Zid Storefront SEO Review

## Mission
Produce a traceable review of search metadata and visible storefront content using the current platform interface, approved merchant facts, and official search guidance. Prepare recommendations; do not apply changes unless the user has authorized execution.

## Required context
Capture platform and admin version, store language(s), target market, page type, live URL, review date, and available Search Console scope. Ask for missing inputs only when they block a factual recommendation.

## Operating steps
1. Read the official platform help article for the exact page type and record its URL and verification date.
2. Inspect the public page and compare visible facts with the native title/description/URL fields. A missing field is a finding, not proof of a ranking defect.
3. Check accuracy, language, uniqueness, user intent, and whether the page should be publicly discoverable. Do not fill a field solely to satisfy a character target or keyword count.
4. Prepare page-specific copy only from supplied or verifiable facts; label assumptions and request factual confirmation where needed.
5. Do not change an established URL, robots behavior, or indexing visibility without explicit approval and a documented risk/rollback plan.
6. Do not inject JSON-LD. If structured data is in scope, first inspect rendered markup and platform support; any markup must reflect visible content and follow current search-engine policies.
7. Recommend a representative test edit, save, inspect the public render, and record the reviewer before scaling.
8. Measure later using Search Console and store data with aligned date, language, URL, and query scope. Never attribute sales or ranking changes to one edit without sufficient evidence.

## Required output
- Executive summary with scope and limits.
- Prioritized issue register: URL, language, page type, observation, evidence/source/date, proposed action, owner, risk, status.
- Copy proposals for human approval, with factual inputs and unsupported claims flagged.
- Change and follow-up log; distinguish saved state, crawled/indexed state, search presentation, and business outcome.

## Safety and quality boundaries
- No guarantees of page-one ranking, rich results, indexing timing, AI citation, or conversion lift.
- No fabricated city modifiers, stock, delivery, discounts, warranties, or popularity claims.
- No generic FAQ stuffing, fixed word counts, keyword repetition, or schema snippets detached from visible page content.
- Preserve existing content and URLs unless approved migration instructions are supplied.
- Platform admin paths are version-dependent; use current official documentation and the actual UI.
